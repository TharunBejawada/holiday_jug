1. EXECUTIVE OVERVIEW & STAGE 1 SCOPE
================================================================================
HolidayJug Stage 1 delivers an inquiry-and-call booking model. Customers search 
for holidays and hotels on the web, see live calculated package prices, and receive 
a unique, cryptographically random 8-character Search ID (e.g. "K9X4M7P2"). 
Online checkout is intentionally replaced by UK phone consultation: customers call 
the dedicated UK sales line (0330 165 8879) quoting their Search ID.
An internal Agent Tool enables sales consultants to look up the exact search 
details, inspect pricing breakdowns, and re-run live supplier checks to confirm 
real-time inventory and pricing differences.

All changes are local only, with zero placeholders, production-grade styling matching 
the Figma specifications, and complete compliance with GRN Connect API V3.

6. TRUE MARGIN PRICING ENGINE (SECTION 6: P1 - P6)
================================================================================
[P1] True Margin Formula:
  - True margin on selling price, NOT mark-up:
    Selling Price = Cost / (1 - Margin)
    Example: Hotel cost 100.00 at 13% margin gives:
    100.00 / (1 - 0.13) = 114.9425... -> 114.95 (rounded UP to the penny).

[P2] Default Margin Rate:
  - Default is 13% applying to hotel price only. Admin configurable.

[P3] Bundle Rules:
  - Zero default margin on flights, transfers, and add-ons.
  - Bundle Total = Hotel Price (with 13% margin) + Local Taxes + Flights + Transfers.

[P4] Local Hotel Taxes:
  - Local tourist/resort taxes are displayed as an itemized line AND included in 
    the total price, ensuring the customer never pays anything extra at the hotel.

[P5] Server-Only Calculation:
  - All pricing calculations run on the server inside pricing.ts.
  - Supplier net costs are stripped via sanitizePricingForClient() and NEVER 
    sent to the browser.
  - All fractional amounts are rounded UP to the penny using Math.ceil(amount * 100) / 100.

[P6] Audit Persistence:
  - For every quote, the system stores: supplier net cost (INR & GBP), margin rate used, 
    currency rate, and UK timestamps.

7. SEARCH ID SYSTEM & AUDIT PERSISTENCE (SECTION 7: S1 - S5)
================================================================================
[S1] Cryptographically Unguessable 8-Character ID:
  - Generated using crypto.randomBytes with unambiguous 29-character alphabet:
    "23456789ABCDEFGHJKMNPQRSTUVWXYZ" (excludes 'O', '0', '1', 'I', 'L').
  - Easy to read clearly over the telephone.

[S2] Results Page Presentation:
  - Prominent Search ID header block on /search.
  - One-click "Copy" button with visual feedback.
  - Message: "Quote this ID when you call us" next to 0330 165 8879.

[S3] Search Record Persistence:
  - Stores customer search inputs, selected hotel, room type, board basis, 
    customer prices, supplier net costs, margins, and timestamps.

[S4] UK Time & Retention:
  - All timestamps formatted in UK time (Europe/London: GMT/BST).
  - Records retained for 30 days (admin adjustable).

[S5] Price Freshness Badge:
  - Every price on the website displays:
    "Price checked at [time] UK, subject to availability".

SECTION 10: DYNAMIC ADMIN DASHBOARD & CREDIT CONSERVATION ARCHITECTURE
================================================================================
1. The Problem Solved:
   - GRN Connect sandbox and production APIs operate on a strictly metered credit model.
   - Repeated calls for static reference data (cities, hotels, facilities, credit limits)
     quickly burn account quota and trigger rate limits.
   - In previous iterations, admin dashboard metrics were static placeholders with dashes.

2. Architecture Implemented:
   a. Local Static In-Memory Index (1,842 Sandbox Hotels):
      - Extracted from `supported hotels on sandbox.xlsx` into `sandbox-hotels-index.json`.
      - Provides instantaneous search and filtering across Dubai (327), Los Angeles (567),
        New Delhi (242), Jaipur (154), Bengaluru (193), Mumbai (178), Chennai (103),
        Kolkata (63), and Luxor (5) without making a single outbound HTTP request.
      - 100% Zero-Credit Browsing.

   b. Caching & Real-Time Search Availability:
      - Search Availability: Executes LIVE in real-time on every search per user request (no caching).
      - Cities & Hotel Master Lists: 24-Hour TTL (`/cities`, `/hotels`).
      - Admin Dashboard Telemetry: 15-Second server cache prevents credit burn on rapid refreshes.
      - Credit Limit Telemetry: 10-Minute TTL (`/credit-limit` fallback telemetry).

   c. Dynamic Admin Dashboard (/admin):
      - Real-time gauge of GRN API credits: allocated (50,000), remaining, and burned.
      - Telemetry metrics: cache hits count, credits saved count, cache efficiency percentage.
      - Real-time Customer Phone Quote Queue: lists live generated Search IDs (`HJ-XXXXXX`),
        UK creation timestamps (`Europe/London`), flight/hotel breakdown, customer price,
        and 13% margin.
      - Direct deep-links into the Consultant Tool (`/agent?searchId=HJ-XXXXXX`).

   d. Sandbox Hotels Explorer (/admin/hotels):
      - Interactive directory of all 1,842 mapped hotels.
      - Filter by city clusters, search by hotel name, address, or GRN code.
      - Optional "Check Rate" action with confirmation warning and 20-minute cache guarantee.

   e. Phone Quotes & Enquiries Queue (/admin/bookings):
      - Replaced "coming soon" placeholder with an active enquiries desk supporting HolidayJug's
        phone-assisted booking model (`0330 165 8879`).

   f. Safe Fallback Resilience:
      - Admin destinations (`/admin/destinations`) and packages (`/admin/packages`) gracefully
        fallback to `DESTINATIONS_MASTER` and `hot-deals-store.ts` when DB is empty, guaranteeing
        that the UI is always dynamic and fully functional.
